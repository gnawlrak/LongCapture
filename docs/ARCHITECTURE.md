# Architecture

## Boundaries

- `AppController`: menu-bar entry, one unresolved result, settings persistence, save serialization and interruption notifications. It never processes screen pixels on the main actor.
- `ScreenCapturePermission`: injectable preflight/request/settings adapters with observable current-process access and reentrant-request protection. Launch and refresh never prompt. Menu/settings expose explicit requests; capture requests access before selection, denial offers the system privacy pane, and app activation refreshes the status. The stream adapter defensively rechecks without prompting after selection.
- App identity: certificate-signed Release and Debug have distinct bundle IDs and display names. Settings display the running bundle's identity and path, rather than assuming a same-named privacy toggle authorizes every build. Build verification rejects hash-bound ad-hoc designated requirements.
- `LoginItemSettings`: opt-in `SMAppService.mainApp` registration, with injectable status/register/unregister/settings adapters. Initialization, settings presentation and app activation only read status, never register. System status is the single source of truth; a pending approval remains cancellable but is explicitly distinguished from enabled. Failed changes re-read actual status and show an inline error. `SettingsWindowController` refreshes on each opening and `AppController` refreshes on activation. No helper, LaunchAgent, persistent enable flag or new privacy permission is added; login launch uses the same accessory-app path as a normal launch.
- App icon: a build-time Swift/Core Graphics drawing produces the ten standard macOS slots in `Resources/Assets.xcassets/AppIcon.appiconset`. Both configurations select `AppIcon`; Xcode compiles the asset catalog and bundle icon metadata. The renderer is not part of the running app. Menu-bar artwork remains the system monochrome template rather than a miniature coloured app icon.
- `NativeGlassView` / `NativeUI`: shared AppKit chrome. macOS 26+ embeds the same content view in `NSGlassEffectView`; macOS 27 additionally enables native interactive glass on floating controls. Older systems use `NSVisualEffectView`. Reduced transparency replaces only the backdrop with an appearance-aware system solid color, observed live without rebuilding controls or changing their targets. AppKit glass bezels and SwiftUI glass button styles retain native focus, disabled and pressed states. No custom motion or screenshot filtering is added.
- `SelectionOverlay`: one display, AppKit bottom-left global selection, local resize/move handles, Return/Escape. Guidance is inset by the greater of the display's menu-bar exclusion (`visibleFrame`) and notch safe area, plus a 16pt gap; tests/fixtures can inject the reserved top inset. The full-display selection origin and extent stay unchanged. `CaptureGeometry` validates and pixel-aligns the rectangle, then converts to ScreenCaptureKit's display-local top-left coordinates.
- Axis detection: the single menu entry and shortcut always start an automatic session. Selection shows automatic-direction guidance, without an axis switcher or a separate horizontal entry; explicit axes remain internal to the core and its tests. Until resolved, `StitchingController` retains the first natural-orientation viewport and at most one reliably matched tiny-motion candidate. It runs the existing estimator plus overlap checks in both orientations, rejects two plausible nonzero axes, and waits for at least four pixels of unique-axis motion before locking, including a seam check. Finish can commit a reliable 1–3px tail without waiting for this threshold; unresolved/no-motion output falls back to the initial image, with recovery warnings retained. Once locked, neither reversal nor rollover can change the axis. Horizontal frames are losslessly transposed into the existing vertical matching/seam engine, then transposed back for sealing, output and references. No wheel-event monitoring, resampling or two-dimensional stitching is introduced. The 50K limit applies along the resolved axis and the 64M pixel cap is unchanged.
- `ScreenCaptureController`: injectable `CaptureFrameSource`; ~15 fps ScreenCaptureKit stream, sRGB BGRA, own-application/cursor/audio exclusion. A nonisolated output adapter accepts only complete frames and copies locked pixel buffers before releasing surfaces.
- `FrameProcessingPipeline`: dedicated serial queue, one in-flight and at most one latest pending immutable image. Finish closes intake after source shutdown/barrier, drains the tail, then renders. Cancel drops pending frames. Main-actor session generation and state checks suppress late callbacks.
- `SessionCoordinator`: explicit idle/selecting/starting/capturing/finishing/result states, source and clock injection, startup/finish/cancel arbitration. An unresolved result cannot be replaced by another capture. Interruptions export confirmed pixels with a warning, not an invented match.
- `StitchingController`: synchronous queue-owned engine. A rejected frame never replaces the last reliable anchor. Exact duplicates and validated zero-rounded shifts are no-ops; a zero-rounded frame cannot replace the integer-coordinate anchor and discard accumulated subpixel motion. Recovery first tries the existing reliable anchor; when that cannot match, it may uniquely relocate inside the confirmed current page. Relocation updates only the anchor and viewport position (including its absolute origin after rollover), never the direction, exported interval or strips. The independent interior-overlap gate also applies to injected estimators, before any position change.
- `FrozenEdgeDetector` / `MatchingInsets`: propose viewport-stationary leading/trailing bands after axis normalization, requiring textured support rather than counting a blank margin as a frozen table. Entirely stationary quantized frames do not learn an inset. A textured band reaching half the viewport, or combined bands leaving less than `max(96px, viewport / 3)` of moving body, makes matching unavailable rather than falling back to the static header. Insets share immutable pixel storage and propagate into Vision proposals, edge sampling, independent overlap, seam selection and recovery; only accepted frames update reliable state. No image pixels are cropped or synthesized. The existing replaceable frontier preserves each outer fixed band once per page. Normal outer-sixth exclusions still apply; frozen regions additionally require at least one fifth of dependable body overlap, preventing a tiny repeated fragment from authorizing a large displacement. This handles full-width/full-height edge bands along one scroll axis, not arbitrary internal blocks or two-dimensional table reconstruction.
- `RecoveryIndex`: built lazily from the current page's committed strips and replaceable frontier after a rejected frame, with at most 32 sampled columns per confirmed row (6.4 MB at the default 50K limit). Informative current-frame pixels propose fully contained viewport origins; each proposal must pass the existing full-viewport overlap validator and real `VisionOffsetEstimator` with zero displacement. Multiple verified positions more than two pixels apart, insufficient texture or too many plausible candidates reject relocation. A candidate viewport is assembled on demand, not by rendering the whole long image. Recovery, finish and cancel clear the cached index; its confirmed source cannot change while paused. Archived earlier pages are deliberately not searched. No pixel, texture, ambiguity or seam threshold is relaxed, and normal growth still requires a verified frontier seam.
- `StitchUpdate`: adds growth/revisit/unchanged/recovering/recovered/continued presentation states, axis, current-page length, page count and per-page limit. A recovery episode downsamples the last reliable viewport once for the click-through/excluded capture toolbar. The toolbar exposes reference content, confirmed extent and near-limit guidance without reporting an invented exact displacement or failure diagnosis.
- Continuation: production sessions opt into `continuesAtLimit`; the single-page core mode remains testable. At a cap the old page is rendered/sealed, the crossing viewport seeds a fresh page with the locked growth direction, and the estimator keeps that exact reliable anchor. The crossing viewport's overlap and overflow are both preserved. Absolute origins order results for reading even when capturing up/left. A carryover-only final page is omitted; reversing after a rollover never creates output in the opposite growth direction.
- `CapturePageArchive` / `CaptureDocument`: sealed PNG pages go into a per-session 0700 temporary directory with 0600 files. The document owns that archive until the whole result is saved or discarded; cancellation explicitly cleans it. Readers load individual pages, not the whole history. A spool failure retains the sealed page plus crossing overflow in memory, stops growth and returns an incomplete group. Forced termination cannot guarantee cleanup or recovery; this is neither a history store nor crash recovery.
- `VisionOffsetEstimator`: up to three spatial Vision registrations propose document-space offsets; one failed/horizontally inconsistent lane cannot veto independently verifiable pixels. Its minimum dimensions are orientation-independent (short side at least 64px, long side at least 96px), so transposing an accepted 96 x 64 viewport cannot reject a short horizontal selection. Each request fails locally; even no usable proposals still permits the bounded pixel search, never an unvalidated commit. Search evidence counts only patches inside each candidate's actual shared body, with at least 24 informative patches, instead of requiring a fixed fraction of samples from unrelated rows. The maximum displacement, interior-overlap requirement and pixel/lane error thresholds remain unchanged.
- Similar-text disambiguation: plausible aliases trigger a denser edge grid and re-ranking against independent overlap pixels, not a confidence/velocity-based guess. Two exact alternatives remain ambiguous. Otherwise, distinguish the winner using strong patch disagreements spread across the overlap, an 8:1 evidence ratio and sufficient vertical support. A second nonduplicating grid phase confirms sparse glyph evidence without reducing the support requirement. A near-lossless winner may provide an error baseline against shorter fragments; a short exact fragment cannot outrank a larger potentially changing body that way. For frozen tables only, a winner with at least twice the alias's body support and independent near-lossless validation may also use glyph counter-evidence across four of six orthogonal bands spanning half the viewport width; this covers distinct table rows whose column labels occupy a narrow strip. Comparable-support candidates use only their common dependable rows. Blank, genuinely repeated, isolated-marker-only and scattered-changing periodic content remain unmatchable. The independent overlap and frontier-seam gates still run before any output change.
- Continuous-image evidence: texture sampling and the sparse recovery index also inspect 8/16px curvature, using the same contrast/support minima instead of requiring only 1/2px glyph edges. A linear gradient has no such curvature. When close offsets look alike, an additional uniform raster grid can disambiguate a near-lossless winner: at least 99% of samples within two RGB levels, RMS at most one level, competing squared error at least 16 times greater, distributed counter-evidence in three row/two column bands, and an 8:1 win ratio. The two-level pairwise ceiling handles separately quantized screen frames, confirmed by a Retina own-window capture; the RMS bound remains one. Refined patches and the independent overlap grid must establish the noise baseline before this path is eligible. This does not remove duplicate-alias, overlap or seam checks. It targets continuous image structure, not arbitrary animated/rescaled content.
- `OverlapValidator`: uses the common interior of both viewports, excluding their outer top/bottom sixths from matching (not cropping those rows from the result). It requires at least 8-24 interior overlap rows, depending on frame height. Texture checks include one- and two-pixel neighbours to avoid paired-pixel sampling aliases. Overlap error uses the worst per-channel error across the original/right/down samples, so neighbours cannot hide a mismatch or dilute the original gate. Pixel/texture/lane thresholds are unchanged or stricter; loss of dependable interior overlap requires recovery, not an edge-only guess.
- Localized parallax: split the normalized cross axis into 12 bands. At most four contiguous differing bands may be proposed as moving captions; every retained band must meet the independent near-lossless noise bound, with at least six textured bands spanning two thirds of the cross axis. Sparse proposal sampling cannot authorize this alone: the separate uniform overlap grid must verify it. Prefer an independently complete near-lossless match over an apparent match that hides a differing label. Alias counter-evidence excludes only the winning proposal's moving band, never the alternative's conveniently chosen band; full-width rigid card boundaries may supply cross-axis counter-evidence under the near-lossless, support-order and 8:1 conditions. A separate raster boundary path requires 96 wins across four of six bands spanning two thirds of the cross axis, with squared-error and noise bounds; genuinely repeated offsets remain ambiguous. Pixel-search early exit only applies when removing even the highest-error allowed four-band interval cannot rescue the candidate.
- Frontier seams now prefer the earliest dependable seam for down/right growth and the latest for up/left growth, retaining the largest replaceable viewport rather than sealing a shifting caption incrementally. Search the normal interior first; only after independent interior registration may a near-lossless full-width seam outside the outer-sixth margin be used. Known frozen bands remain excluded. Caption-masked registration never masks a seam: localized-motion seams must be independently near-lossless across all bands. If animation crosses every possible seam, leave the anchor, bounds and pixels unchanged and request recovery. There is no per-region warping, DOM access, inpainting or general animation removal; the final viewport can retain a caption's current fade state.
- `StitchState`: signed current viewport origin, locked growth direction and independent exported upper/lower extents. Immutable strips hold committed content; a replaceable frontier holds the viewport at the growing end. Growth finds a verified interior seam, commits the old frontier only through that seam and takes the remaining growing side from the new frame. Reverse visits move the reliable anchor without replacing the frontier. Failed seam checks change neither position, bounds nor direction. The final sRGB RGBA image is assembled once; no growing full-image redraw occurs during capture.
- `ResultLifecycle`: injected monotonic clock; thumbnail countdown, pause, preview, saving and resolved transitions. Failed saves require an explicit retry instead of endless auto-save attempts.
- `ResultStore`: ImageIO PNG encoding, same-directory private staging file, fsync, atomic no-replace rename, collision suffixes and deferred staging cleanup. Image ownership stays with the app until success or acknowledged discard.
- Result groups and segmentation: one original page keeps the existing single-PNG path. Multiple originals or a segmented export use a private same-directory staging folder, write numbered PNGs one page at a time, then publish with one no-replace directory rename. Failures remove staging but retain the source document. `SegmentExportOptions` validates 256–20K pixel lengths and 0–half-length overlap; crops follow the capture axis without resampling. Export is an additional copy, not resolution of the original result. The UI blocks conflicting close/save/discard/quit actions during export and permits explicit retries or directory changes afterwards.
- `ResultThumbnail` / `PreviewWindowController`: native nonactivating thumbnail and AppKit read-only scroll/zoom/copy/save/discard window. Close routes through one async save. Discard needs ownership acknowledgement so an external save cannot strand the preview.
- Multi-page UI: the thumbnail reports group count; preview switches pages via a native popup, loading disk pages off the main actor and restoring the selection after read failure. Copy applies only to the visible page, while save/normal close resolves the whole group. Horizontal preview fits height, vertical fits width. Exported copies survive a later discard of the original document.
- `SettingsWindowController`: a retained SwiftUI hosting child inside shared glass chrome, with a transparent grouped form and native glass buttons. The resizable window keeps permission identity, path disclosure and shortcut-recording cancellation intact. Preview/settings use transparent full-size titlebars and respect the content safe area.

## Invariants

Sparse-landmark fallback supplements low-density viewports without frozen insets. A bounded 12 x 12 tile scan retains at most 32 contrast anchors; at least six 5 x 5 patches must all match within two RGB levels and RMS one, distributed across two motion bands and all three cross-axis bands, spanning one third of the real interior overlap and half the width. The independent uniform overlap must also be near-lossless; normal offset ambiguity, overlap size and full-width seam checks still apply. Sparse samples propose offsets only. Historical recovery can replace half of its regular columns with up to sixteen query-informed columns, keeping the same 32-column / 6.4 MB cap; it still verifies a complete already-confirmed viewport and rejects multiple positions. Blank, isolated, periodic and changed marks are regression negatives, not exceptions to force through.

Gallery boundary evidence supplements (not replaces) the regular texture grid. For viewports without frozen insets, scan cross-axis curvature at 8/16px, retain at most sixteen separated boundary rows and forty-eight points per row, and validate their full 16px extent within both candidates' real interior overlap. A boundary witness requires four matching points in each of at least six of twelve bands, spanning two thirds of the cross axis, within the existing two-level pairwise noise limit. Its offset also needs the independent near-lossless overlap validation. Only an at-least-as-large witness can eliminate a shorter, boundary-less white fragment; periodic supported alternatives remain subject to the normal ambiguity checks. Test likely Vision offsets first to avoid hundreds of expensive uniform-grid checks on empty fragments. Frozen tables keep their prior path. No DOM, scroll events or page-specific coordinates are used by the App; those belong only to the isolated public-page acceptance probe.

1. Positive internal displacement is document-down (document-right after horizontal normalization); first nonzero reliable displacement fixes the growing side and rollover cannot change it.
2. Reliable viewport position is not output length. Reversals never reduce the captured interval.
3. No unvalidated displacement may append pixels. Mismatch retains its anchor and marks an unfinished result incomplete.
4. Each normalized page height is `min(50_000, 64_000_000 / normalizedWidth)`. Cropped partial strips reach the exact cap; a continuation viewport preserves all overflow with overlap. The first oversized viewport stops safely instead of violating the per-image limit.
5. Screen sample buffers never escape their callback; images own copied bytes. Only the processing queue touches stitching state.
6. Ending includes the latest accepted pending complete frame. Cancelling invalidates the generation before awaiting source shutdown.
7. An active result outlives a failed save and blocks new capture. Save, close and discard are idempotent at the owning UI boundary.
8. No screenshot or document content is sent anywhere. There is no networking code or third-party runtime package.
9. A permission request's acknowledgement is not sufficient to unlock capture: current-process preflight must succeed. Only screen-recording access is explicitly requested, and no system permission is modified on the user's behalf.
10. During normal capture retained core pixels are bounded by one page plus at most two viewports (frontier and anchor usually share immutable Data); recovery may additionally retain one sparse index of at most 6.4 MB with the default limits and transiently assemble one candidate viewport. Previous pages occupy disk, not growing pixel buffers. A spool failure retains at most the sealed page and next viewport before ending. Rendering/axis transpose, estimation, source/pipeline buffers and final preview loading require additional bounded allocations; this retained-pixel invariant is not a process-RSS claim.
11. A seam can replace previously covered edge pixels only when a later reliable frame actually reveals them. Confirmed viewport-fixed edge bands are retained once at the corresponding page edges; initial/final occlusion may remain. Arbitrary internal fixed elements or continuous animation are not automatically erased or reconstructed.

## Build

The root `LICENSE` covers LongCapture under MIT. The App resources include both that license and `THIRD_PARTY_NOTICES.md`, preserving ScrollSnap's separate upstream copyright and MIT notice in source and binary distributions.

The shared Xcode scheme contains an App target (macOS 14) and a hosted XCTest target. Building the glass implementation requires Xcode 27 / macOS 27 SDK; availability guards preserve the macOS 14 runtime deployment target. Tests skip production status-item/hotkey initialization. Debug uses the current architecture and the `.debug` bundle ID; `scripts/build.sh` produces an optimized, Apple Development-signed local app using the configured team. Test-only code and entitlements do not enter the Release app. `scripts/test-signing.sh` mutates and re-signs a disposable, never-launched copy to verify that the designated requirement stays stable across content changes; this does not prove an actual TCC grant.

`scripts/render-ui.sh` compiles a separate fixture executable from the real UI sources and a generated document. Its default snapshots test offscreen layout, not compositor effects. The optional compositor mode preflights existing access without prompting and uses an explicit two-window ScreenCaptureKit inclusion filter, checking both windows' owner PID. Only the generated backdrop and the fixture window are captured. Selection/toolbar fixture instances temporarily allow sharing for this inspection and restore it afterward; production instances remain excluded and are checked by XCTest. The fixture does not enter the application bundle.
